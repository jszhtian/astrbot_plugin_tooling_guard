# Tooling Guard

**一句话**：模型想调用 shell、python、读写文件、浏览器、截图点击这类高危工具时，本插件在工具**真正执行之前**
先判一次，把「放行 / 拒绝 / 等人批」和判定依据写进审计库。默认只审计，不拦。

更新记录（每个版本改了什么、为什么）见 [`CHANGELOG.md`](CHANGELOG.md)；面板的插件详情页直接读这个文件。

## 1. 装好之后会发生什么

每个受管调用都会落到下面四档之一：

| 处置 | 你会看到的样子 |
| --- | --- |
| **通过** | 工具照常执行，审计里留一条记录（工具名、参数摘要、判定依据）。 |
| **拒绝** | 工具不执行，模型收到一段拒绝理由。只有静态层会这样直接拒绝（黑名单、路径黑名单、凭据、敏感配置等），审计写明命中的是哪一条。 |
| **等待审批** | 工具先挂起，管理员收到一条私信，**直接回复「同意」就放行、「拒绝 <原因>」就拒绝**（多条待批时回「同意 <票据前 8 位>」）；也可以用 `/guard approve|deny <票据>`。模型拒绝、或两个模型都没结论时走这一档（票据会写明是哪一种）。最长等到 `min(suspend_timeout_s, 110)` 秒，**超时一律按拒绝处理**。批准与「同会话 + 同工具 + 同参数」的一次调用绑定，且**由网关自己执行**（0.7.3），不需要模型重发；剩余预算不够执行时才退回「请原样重发一次」的提示。 |
| **降级观察** | 配置校验没过、钩子安装降级、审查器忙或超时等情况下，工具**照常执行**，只留一条带 `degraded=` 标记的审计行并告警管理员。这种行不代表「判定为允许」。 |

在默认的 `observe` 模式下，本该拒绝或挂起的调用不会真的被拦，只在审计里记成「本该如此」（`would_be`）。

### 三层审查怎么判（0.6.0 起，0.6.4 定案）

判定只有三层，三层看的是**同一份输入**：静态检查（策略 + 规则）→ 快审（`jev`）→ 深审（LLM）。

- **只有静态层能自动拒绝**：用户黑名单、`path_deny`、私钥/凭据内容、敏感配置读取、`strict_path_whitelist`、
  「下载或解码 + 执行」这几类直接拒绝，其余一律交给模型。**白名单是唯一的静态通过**，命中的调用不再问模型。
  没有「强工具一律挂起」那条默认判决了：shell、python、文件读写不再因为工具名就被送进人工队列。
- **一票放行**：任一模型说「可放行」且没有模型说「拒绝」，这次调用就放行。
- **模型拒绝不是硬拒，而是开票问你**：票据上会写「模型审查拒绝了这个调用，但它不在静态拒绝项内——这是一次
  高风险操作，放行必须由你显式同意」。
- **两个模型都没结论也开票**：票据上会写「出现了一个非常规操作，模型没有给出明确结论」。
- **弃权不是拒绝**：模型超时、报错、回答读不出，都只算「没有意见」，既不放行也不拒绝。
- **深审只在需要时跑**：快审弃权、或快审要求再看一眼时才启动深审；快审自己就拒绝时不跑深审（省掉一次模型往返）。
- **快审的中间分档一律弃权**（0.6.1）：分数落在放行线与拒绝线之间时它不投票，一定交给深审定；深审也弃权才开「非常规操作」的票。旧行为是中间档直接按 `noul` 分成放行或挂起，于是一次无害的 `web_search` 也会进人工队列、深审永远轮不到。
- **超预算不硬拒**：三层共享 `decision_budget_s`（默认 120 秒）；预算耗尽或判定内部异常时按「没有结论」开票问人，
  而不是回一个假的拒绝。
- **看得见每一层说了什么**（0.6.1）：Web 票据详情给出「执行了什么」（脱敏后截断的参数）与快审/深审各自的
  结论、理由、分数、把握度；审计表列不变，这些细节只在 `summary_json.review` 里。
- **投递留痕**（0.6.1）：通知成功写一条 `notify_sent`、失败写 `notify_failed: <原因> | <管理员>=<结果>` 审计行。
  宿主 `Context.send_message` 对不存在的会话也返回成功，所以「没报错」从来不等于「送达」。
- **私信按平台逐个试**（0.6.2）：管理员只写裸 id 时，网关不再盲用触发调用的那个平台，而是先试聊天平台、
  再逐个试宿主正在跑的平台；只落在面板平台（`webchat`）上的「成功」不算送达（记 `ephemeral`）。
  面板/webchat 里测出来的调用不会再静默丢掉私信。
- **快审的低置信度也弃权**（0.6.2）：分数再怎么极端，只要快审自报把握度低于 `fast_min_confidence`，
  它就不投票、交给深审（旧行为是低置信度直接挂起等管理员，于是无害调用也会进人工队列）。
- **票据详情不再为空**（0.6.2）：详情优先取「挂起且带摘要」的那条审计行；通知里的动作/层级也渲染成
  中文（查询 / 执行 / 未定级），不再是每个工具一律「未知动作 · 未定级」。
- **两个模型都能看到同一会话的前几次调用**（0.6.4）：网关给每次调用记一条轨迹摘要，判定时把该会话最近 8 条
  渲染成 `trajectory_summary` 放进**同一份输入**，快审和深审拿到的是同一段历史。所以「先读敏感配置、紧接着
  外发」这种单次调用看不出的序列，模型也能看见（0.6.4 之前窗口从未真正建立，历史永远是空的）；历史只进
  模型输入与审计，不改判决表，也不进 Web 出网字段。
- **「先读敏感文件、紧接着外发」必定强审一次**（0.6.6）：这类序列由 R7 判（30 秒窗口内的敏感读取 +
  外发通道）。它**不在静态拒绝项里**，所以只打标签、不自动拒绝；但只要命中，网关就强制把这次调用送进深审，
  快审说「可以放行」也照样送。深审说拒绝 → 开「模型审查拒绝了这个调用」的票问你；深审也弃权 → 快审那张
  放行票仍然有效（一票放行）。想让它变成硬拒，就把那些路径写进 `path_deny` / 用户黑名单。

- **归因看层级，不看规则号**（0.6.7）：审计行的 `rule_id` 是「第一个命中的规则」，而 observe 类规则
  （R8 目录列举、R4 编码执行）命中并不拦人，拿它当拒绝原因就会把账算到观察者头上。每次判定现在另带一个
  归因层（`summary_json.attribution`，含 stage / layer / source；summary_line 尾部另有 `layer=<层>` 标记），
  `rule_ids` 同时标成 `evidence`。通知里先写「归因 <层>」再写「命中规则」，统计先给「归因层 Top」再给
  「命中规则 Top（证据，非归因）」。
- **回执里也说归因**（0.6.8）：0.6.7 只把归因写进了审计与通知，模型拿到的工具回执仍是
  「… [rules=R8]」。线上实测：模型把这句原样转述成「被 R8 规则拦下了」，还建议去改一个无关设置。
  现在 `main._spoken_reason` 在拒绝/挂起回执末尾补一句「（归因 static/deny_path；规则号 R8 只是证据，
  不是原因）」，放行的回执不加。
- **未纳管通知可以关掉**（0.6.9）：cron 唤醒、后台任务这类在网关之外发生的调用，每次都会私信一条
  「[工具网关] 未纳管侧的工具调用已被观察」，一个计划任务里每调一次工具就是一条。新增开关
  `side_notice_enabled`（默认开）：关掉只停这条私信，**观测照样记录、审计行照写、判定与放行完全不变**
  （跳过的通知在观察对象上记 `skipped=side_notice_disabled`）。
- **快审可以交给 AstrBot 自己的模型**（0.7.0）：快审不再必须是第二个端点。新增两个接入方式键，
  各自只对自己的后端生效：`jev_source`（后端 `jev` 时用）= `endpoint`（原来的原生 System One 端点）或
  `astrbot`（用 AstrBot 4.29.4 新增的**决策模型**Decision Provider，一次 `ask` 同时取回风险分与深审建议）；
  `llm_fast_source`（后端 `llm` 时用）= `endpoint`（原来的 OpenAI 兼容端点）或 `astrbot`（复用宿主里的
  **对话模型**，只要求它回一段 JSON）。两种内置方式都只需在宿主里配一次模型，不用再往插件里贴端点和密钥；
  留空即用宿主的默认模型，也没法用面板下拉挑决策模型（面板的模型选择器只列对话模型），所以要指定就手填提供商 ID。
  **判决口径完全不变**：两种内置方式返回的还是同一份 `FastVerdict`（分数 / 深审建议 / 把握度），分档、
  置信下限、深审触发都仍在 `jev.score` 里，没有为谁单独写一套。`jev_enabled` 关掉时三种来源一律不跑。
- **批准即执行**（0.7.3）：以前管理员点「批准」，网关只回一句「请重新发起一次完全相同的调用」，指望模型
  把上一轮参数逐字节复现。线上 2026-11-04 的 5 张票只有 1 张重放成功（发 12 KB HTML 那张 100 秒后重发时把
  `path` 丢了），还有一张被提示后改参数绕开审批。现在批准的那份参数由网关自己执行，模型收到的是「已执行」；
  预算不足时才退回「请原样重发」。批准后 5 分钟内同键不同参数再次出现，审计标签加 `changed_after_approval`。
  开关 `execute_on_approval`（默认开）。
- **深审不再空转**（0.7.3）：深审输入是裸 state JSON，聊天模型会把它当成用户请求去执行（实测
  `deepseek-v4.1-flash` 回 "I don't have a `comfyui_status` tool available…"、92.2 秒长散文），
  解析不出 JSON 就弃权，快判也弃权 → 全部开票。现在数据围在 `---- BEGIN DATA ----` 围栏里并明确
  「你是风险评分器，不执行、不拒绝」，首次读不出分数用剩余预算再问一次；`72`/`72.0`/`"72"` 都算同一答案。
- **待批票据的通知不再被限频吞掉**（0.7.2）：限频表按 (主体, 工具, 模式, 判类, 票) 归并告警，而「降级类」
  恒把票据号从键里丢掉，于是同一请求者 10 分钟内第二次挂起（换了新票也一样）会被静默合并：没有私信，
  审计表里也没有任何一行，票照旧等满 110 秒超时。现在挂起通知（decision=SUSPENDED 且有票）一律按票号分桶，
  永不合并；被挡下的其它告警也会留一行 notify_merged，写明窗口长度。
- **配置页先决定用谁、再填地址**（0.7.1）：`fast_judge_backend` 与 `llm_fast_source` 挪到 `jev_base_url` 之前，
  两个 `*_provider_id` 也排在端点地址之前，`jev_api_key` 与 `jev_model` 相邻。旧顺序把端点地址夹在
  「协议」与「接入方式」中间，看起来像先填地址再决定协议，与实际读取条件相反。**只换顺序，键名与
  默认值一个没动**，已有配置不需要改。
- **路径目标必须是盘符或 UNC 形态**（0.6.7）：重定向符是从命令文本里读出来的，所以 python 里的比较运算
  `where ts > '2026-10-30T19'` 曾被读成「把输出写到 2026-10-30T19」，那个碎片进了 targets，再被 `path_deny`
  判一次。现在只有写成盘符/UNC 的 token 才算路径目标；相对写目标（`> out.txt`）仍留在 `write_targets` 里
  供写入类规则使用，只是不再进 denylist 的判定集合。

## 2. 最少要配什么才能用

- **`mode`**：默认 `observe`（只审计）。要真拦就改 `enforce`。
- **`admins`**：**切 `enforce` 的前提**。`admins` 为空时配置校验不通过、网关不启用——退化成上面的
  降级观察（工具照常执行、**不做判定**，审计行带 `degraded=gateway_disabled`），不是「判定后放行」。
  批准票据还要求宿主侧管理员**和**这份名单同时命中，所以名单别留空。
- **`project_roots`**：填工作目录的**绝对路径**。留空插件照样启动、照样真判定，但「项目根信任域」永不生效、
  路径污点也不覆盖任何路径。
- **`path_deny` / `path_whitelist`**：只能填**绝对路径**。相对路径、`~`、`%VAR%` 会被判致命项——
  网关直接不启用、退化成上面的降级观察。
- **`suspend_timeout_s`**：等审批的秒数，1–110，**只会缩短上限、绝不放大**，越界直接拒绝而不是悄悄钳制。
- **`jev_enabled`**：快审总开关（三种来源共用）。关掉时快审这一层不跑，判定只剩静态层与深审。
- **`jev_base_url` / `jev_model` / `jev_api_key` + `fast_judge_backend`**：自填端点时的快审
  （**一次**请求，同一次响应里取回风险分、深审建议与把握度；单次上限见下面的 `jev_timeout_s`）。没配齐就不跑快审，
  判定只剩静态层与深审。`jev_base_url` 现在是**完整 endpoint**（如 `http://127.0.0.1:4500/v1/systemone`），
  程序按原样发出、**不再**拼 `/chat/completions`；只填到 `/v1` 这类基址会打到错误路径，而协议走错
  **不报错**，只会一直拿到弃权——弃权不是拒绝，只是「这一层没有意见」，两层都没意见时才开票问管理员。`fast_judge_backend` 选协议：`jev`（默认，把结构化
  JSON 状态 POST 给原生端点，读 `risk` 分数与 `deep` 建议）、`llm`（OpenAI 兼容 chat/completions，
  要求模型只回一段 JSON）；填这两个以外的值配置校验失败、网关不启用。
  **这三项只在「走自己端点」时需要**（0.7.0）：后端 `jev` 且 `jev_source=endpoint`，或后端 `llm` 且
  `llm_fast_source=endpoint`。改用 AstrBot 自带模型（`jev_source=astrbot` / `llm_fast_source=astrbot`）时
  这三项留空不再报配置错误，`jev_provider_id` / `llm_fast_provider_id` 留空即用宿主默认模型。
  宿主上要么先配一个 decision 类型的模型提供商（`jev_source=astrbot`），要么有一个可用的对话模型
  （`llm_fast_source=astrbot`），否则每次快审都失败并按**弃权**处理（弃权不是拒绝）。
- **`jev_timeout_s`（默认 10，1–50）**：一次快审最多等多久。**本机自己跑的判定模型冷启动可能十几秒**
  （Ollama 首次加载约 15 秒），稳态大约 0.6 秒/KB（6 KB 状态约 3.6 秒）。上限 0.6.0 起从 30 抬到 50，就是
  为了容纳冷启动；端点在冷启动就把调高到 30–50。**超时算弃权**：既不放行也不拒绝，交给下一层；越界或非整数
  是致命项，网关不启用。
- **`fast_allow_score`（默认 30）/ `fast_block_score`（默认 75）**：风险分归一化到 0–100。低于放行线
  直接放行、达到拒绝线直接拒绝，中间那一档**不投票**（0.6.1 起一律弃权，交给深审；旧版按 `noul` 分成
  放行或挂起）。`noul=true` 在任一档都表示「请深审再看一眼」。两档相等或倒置是致命项
  （`fast_thresholds_inverted`），网关不启用。
- **`fast_min_confidence`（默认 0.6）**：快审自报的把握度（0–1）。低于下限时**一律不投票**（0.6.2 起，
  放行档与拒绝档都一样），交给深审；审计行仍留一条 `degraded=fast_low_confidence` 当证据。端点漏报
  confidence 时这道门不生效、只留一条 `confidence_missing` 证据——**没报 ≠ 有把握**，换端点前先确认它会报。
  **代价**：快审的极端结论会因低置信度失效，一次本该立刻拒绝的调用要等深审表态，深审也弃权才进人工队列。
- **`llm_enabled` / `llm_provider_id`**：深审。`llm_provider_id` 留空就用宿主的默认模型（网关把宿主
  Context 交给深审客户端才能解析这个默认值；早期版本没交，结果每一次深审都抛 `TypeError`、被断路器
  统一报成 `judge_unavailable`）。

名单、目的地白名单、Web 页面、保留期这些按需再配；配置页上每个键都有中文说明和代价描述。

## 3. 覆盖边界

- **管不到的**：cron 轮次、后台唤醒、子 agent 内部的工具调用**不经过**这个钩子，网关看不到也管不到。
  不要把它们算成「已覆盖」或「已审阅」。
- **不可纳管工具默认原样放行（本次请求照常可用）**：MCP 工具、handoff（`transfer_to_*`）、后台任务工具、
  `future_task`、形态识别不出的工具——五类一样对待：不装代理、不审计、不进策略，安装期只打一条
  `N 个不可纳管工具原样放行（不进入审计与策略）` 的 WARN，并逐名列名。
- **想改回剥离就把 `strip_unmanaged_tools` 打开**（`_conf_schema.json:14`，默认 `false`）：五类一起剥离，
  并打一条 `开关 strip_unmanaged_tools 已开启，剥离 N 个不可纳管工具` 的 WARN，提示这些工具本轮不可用、
  也不留审计行。这个开关是**单向的全有或全无**：不能只剥 MCP 而保留 `future_task`。
- **放行的代价**：这些工具在网关之外执行——没有策略判定、没有审计行、没有污点记录。「放行」是
  「宿主照旧执行」，不是「已经审过」。

## 4. 不保证项

- 不保证每个请求都被覆盖：钩子是否派发由宿主决定，宿主会吞掉钩子异常，canary 只证明本次请求派发过。
- 不保证 cron / 后台唤醒 / 子 agent 内部：不经此钩子，既不审计也不阻断。
- 不保证 MCP 服务器工具、`HandoffTool`（`transfer_to_*`）、宿主后台任务工具与 `future_task` 被审批：
  出厂默认它们原样放行，就在网关之外执行；打开 `strip_unmanaged_tools` 才剥离，而「本轮不可用」同样不等于「已审批」。
- 不保证判定正确：规则是模式匹配、快审是一次可配超时的模型调用（`jev_timeout_s`，默认 10 秒），两者都会误判；observe 期数据是切 enforce 的唯一依据。
- 不保证深审一定发生：它是三层里的第二层模型，只在快审弃权或要求深审时跑；判定总预算（`decision_budget_s`，默认 120 秒）不够时它不跑，那一次判定就只有第一层的意见——第一层也没结论时最终是开票问管理员，不是自动放行。
- R8 只对「命令级只读」例外：首词命中只读词表（`Get-ChildItem` / `Select-String` / `Get-Content` / `rg` 等，命令级分类里 `READ_ONLY_COMMANDS`）且携带的每个绝对路径都落在 `project_roots` 内的命令不再触发 R8；查不出的形态一律保守地照旧触发（写/删/执行动词、重定向、未加引号的 `>` 与 `$(`、词表外工具、空 `project_roots` 全部不变）。R8 从来只是 observe 级观测加同步深审触发，去掉它不放开任何调用。
- 深审输入现在保留域外片段：`project_roots` 之外的绝对路径会被换成 `<EXT>/<basename>` 占位符、过同一套秘密扫描与脱敏、按 2 KB 截断后**进入深审**，census 记 `outside_project_roots_kept`。代价是模型真的看到了域外内容，只由占位符与截断约束；命中秘密的片段仍在改写之前丢弃，空 `project_roots` 仍全丢，`no_fragment_in_scope` 只在没有任何片段幸存时出现。
- 不保证不误剥离：形态识别依赖上游实现细节，上游改实现时靠指纹兜底，失配即改为一律拒绝，而不是静默放行。
- 不保证迟到裁决会回填模型上下文：迟到决定只落审计并通知管理员，模型看不到。
- 不保证穷尽未知包装形态：分类器只做分类，不剥离也不放行，认不出的形态一律落到「不纳管」。
- Web 票据详情只出脱敏后的 `args_head`（截 512）与各审查器的一句话结论（`summary_json.review`）：
  完整参数、`args_digest` 与原始 `summary_json` 仍在出网白名单之外，要查得用 `/guard status <票据>` 与库内取证。
- 读取路径不产生 `allow_*` 审计行：成功读不落任何放行行，无身份的读只落一条限频的 `deny_requester`。
- 不保证能阻止绕过钩子的任何调用：cron、子 agent、宿主内部直接调用都不受本插件约束。
- 代理留在工具集里靠的是「最后注册」：后装的插件若把同名工具塞回去，代理会被换回原工具，本次请求不再受管。
- `yield_time_ms` 只在能拿到剩余预算时才被钳制；拿不到预算就不钳制、只记日志，超长等待仍靠宿主兜。
- 深审给不出结论（超时、异常、回答读不出）一律算**弃权**：不顺延成拒绝，也不据此放行。
- 剥离失败还有第二级兜底（三级清空），但三级都没能证明为空时只记 error，仍不是「保证不可用」。
- 相对路径按宿主会话工作区解析，拿不到根就按拒绝处理；自定义/项目工作区这种部署下根取不到。
- 凭据 glob 不含备份副本：`id_rsa.bak`、`id_rsa.txt` 能被 `glob=*.txt` 命中却不判凭据命中；按 path 直接指定仍判拒绝。
- 不保证污点匹配的精度：短文本仍可能漏配或误配（跨会话串味已修）。
- 审计 drain 仍可能被事件循环拖住：单次最坏冻结约 150 毫秒量级，写库没有搬到工作线程。
- 单个参数超过 256 KiB 时，落在其后的秘密不会被命中——但这种调用是**被拒绝**，不是被漏放。
- 事件循环上的写最多等一个 worker 持有的锁，没有硬实时上界。
- 批准人另有列、批准行回到请求者：自批会被标记 `self_approved`。
- 启动清理先过期、后作废：批准窗口已自然关死的票据重启后仍是「已过期」，不会被改写成「启动作废」。
- 没有存活等待者的批准会撤回重试窗口（`retry_window=withdrawn reason=no_waiter`）。
- Web 控制台没有自己的 CSRF token：身份只来自宿主注入的用户名，安全性委托宿主会话与同源策略；
  **前提是面板只从本机访问**——一旦反代到公网，任何能登录面板的账号都能读全部审计并批准任何票据。
- 观测心跳断言在极端负载下可能瞬时抖动：属测试时序，不是产品缺陷。
- 仍未关闭的易用性 nit：cron 轮次既不装代理也不剥离；`/guard status` 的挂起提示仍写死「最长 110s」，不按实际剩余重算。

## 5. `/guard` 速查

除 `/guard whoami` 外仅 `admins` 里的账号可用；其他人调用只会拿到固定拒绝文本加一行自身诊断，并留一条拒绝审计行。
`/guard whoami` 任何发送者可用、纯只读、不留审计行。

| 命令 | 作用 |
| --- | --- |
| `/toolguard` | 版本、网关状态、当前模式、模型路由。 |
| `/guard whoami` | 任何发送者可用：一行报出你的主体、平台 id、消息类型、发送者 id、名单与宿主管理员是否命中（能否使用 `/guard`），被拒时再给一行建议。只读、不留审计行。 |
| `/guard status` | 网关概览（4 行）：模式及含义、是否启用、告警数、启动清理、信任门、JEV 快审与深度复核开关、审查器单行、覆盖边界。 |
| `/guard status <票据>` | 只读查看单个票据（3 行）：状态与批准窗口、工具名与创建时间、裁决人与理由。 |
| `/guard stats [24h\|7d\|all]` | 审计统计（默认 24h）：判定、规则、路由计数与待决票据。 |
| `/guard approve <票据>` | 批准挂起票据（只对一次同参数重试生效）；与私聊回复「同意」走同一条迁移。 |
| `/guard deny <票据> [原因]` | 拒绝挂起票据，可附理由。 |
| `/guard sweep` | 重新跑启动清理、重新打开批准闸门；只作废启动前创建的票据，不取消活票、不复活旧授权。 |
| `/guard mode` | 显示当前模式与含义。 |
| `/guard mode observe` / `/guard mode enforce` | 切换模式；`enforce` 需要 `admins` 非空。 |
